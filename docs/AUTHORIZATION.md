# Authorization source boundary

Private Dirty source checkpoint, runtime-unverified. Delegated source approval
does not waive independent P0, authorize instrument execution, spend, keys,
accounts, model activation, network or publication. Current ceiling is USD 40;
authorized spend is USD 0. No product code has been imported/run for this checkpoint.

`m11.authorize.check_authorization` accepts closed registration/suite/schedule
records and explicit `AuthorityEvidence` references. It reports digest/pin/gate
defects and missing evidence, but always returns `eligible=false` in this phase.
Even simulated instrument execution is refused. No caller boolean, receipt-shaped
object or source-approval flag can activate runtime. Changing this boundary is a
future explicit authorization/review task, not an environment toggle.

Before future runtime, independent P0 must pass, free RAM must be checked (alert
Roy below 3 GB) and Roy must be told. Future held-out opening also requires distinct
full-pack admission, sealed custody, frozen suite/schedule/treatments/analysis/pins,
no exposure, and affordable complete-stage bounds. Full-pack PASS alone opens
nothing. NO-GO and SKIPPED consequences remain as specified in the protocol.

Future native stages additionally need approved exact account/model/terms and
credential-reference path, model response coverage, isolation/delivery evidence,
complete usage/nested-retry coverage, signed activation/tranche, finite liability,
and M9 cumulative headroom including paid outside work. Stage A itself requires
an external hard billing limit. No current evidence has been established here.
Do not read credential files to make a gate appear complete.

No M9 bytes are staged. `m11.accounting.load_ledger()` exposes an unavailable port;
reserve, begin, settle, snapshot and export all refuse. Price estimates, metadata
SQLite and public result exports cannot authorize money or fabricate balances.
Unknown liabilities retain full reservations; estimates never release headroom.
Exact private M9 intake is requested; see [VENDORED](../VENDORED.md).

`MetadataStore` implements a global serial lifecycle within its SQLite database.
Claims/running/cleanup_pending block new claims; durable begin is never replayed;
all attempted cells remain consumed even after failure/refusal. It is metadata,
not permission to dispatch. The future controller alone may launch/kill after
all external authority and cleanup gates. No host-native fallback is introduced.

`PublicExport.eligibility` separately binds admission and result-embargo provenance.
It cannot infer independent rights/signatures from hashes, rejects caller-asserted
PASS, and supplies no currently released MEASURED outcomes. SIMULATED is descriptive
only. Hidden results remain in custody until frozen final analysis; later public
release is a separate manual/rights decision.

Deferred: actual independent appointments/signatures/admission, current-pin and
scope authentication, SQLite concurrency/crash durability, cleanup/kill isolation,
M9 source and copied tests, native model/usage/billing proof, installed-wheel and
all runtime K/L checks. Static parsing is not any of those results.
