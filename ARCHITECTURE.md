# M11 architecture

Source construction is authorized; runtime is unverified and independent P0 remains pending. No measured result or instrument acceptance is established. Python3.12 with Pydantic2 data contracts and an argparse entrypoint is the selected stack; dependencies are declared during construction, not installed or executed.

`harnessrun` is a standalone closed-contract closure with no private evaluation imports. `m11.contracts` exposes the shared data types. Adapters describe capabilities, prepare launch data and parse bounded observed streams; they do not spawn. Null/scripted modes remain SIMULATED. Native identity, memory, usage and finite-spend-bound evidence stays unknown unless separately proven. The controller alone owns future process lifecycle and termination, after all activation gates.

`m11.campaign` owns explicit versioned registration, suite/item, schedule, seed/checkpoint and public-export bindings outside the closed harnessrun format. Scheduler/preregistration/store modules preserve every planned slot, exact frozen identities, amendments, ambiguous begins and missing outcomes. Longitudinal trajectories carry only permitted source/treatment state, continue candidate failures and stop on infrastructure loss with unknown remaining cells. Authorization distinguishes a source-construction ruling from admission, runtime, model, billing and monetary activation.

`m11.accounting` adapts the exact pinned M9 ledger as the sole money authority. An absent closure, unknown liability or missing authorization refuses monetary dispatch. A report estimate never releases reservation headroom or substitutes for a ledger. The USD40 app ceiling includes all tranches and external costs; no spend is currently authorized.

`evaluation/` is a separate source-only evaluation closure outside the wheel. It handles admission formats, custody and trusted grading boundaries without importing private answers into adapters or public exports. Builder-owned development material has explicit lineage. Independent P0/held-out tasks, expected behavior and arithmetic require external authorship and human rights/semantic review; no builder or builder child supplies that independence.

Pure public `m11.analysis` and `m11.rot` retain task/class weights, all-attempt costs, missingness bounds, exact metric versions and explicit unavailable reasons. Reports render escaped HTML/Markdown/JSON and inline SVG from public result exports. SIMULATED inputs never become inferential research tables, and unknown costs/models do not become zeros or verified evidence.

Dependencies flow from contracts and frozen campaign metadata to adapters/controller/scheduler/analysis, then to reports and CLI. CLI imports consumer operations lazily and returns truthful refusal for missing dependencies/gates. Future tests must exercise installed-wheel/public evaluation boundaries, isolation, cleanup, refusal and independent metric references before any acceptance claim. None has run in Dirty construction.

Agent coordination, decisions, immutable plan/status, source grants, deferred checks and transcripts live in the private OUTER shell. Product code stays in the INNER repo and assigned local worktrees. No credentials, raw private transcripts, independent hidden data, remotes or publication artifacts belong in the product tree.
